## ADDED Requirements

### Requirement: User, Session, Account, and Verification MikroORM entities exist in libs/users
`libs/users` SHALL export MikroORM `@Entity()` classes for the four Better Auth core tables (`user`, `session`, `account`, `verification`) with column names matching the Better Auth schema exactly (snake_case columns mapped via `fieldName`).

#### Scenario: Entities registered in MikroORM
- **WHEN** the users-subgraph starts and MikroORM discovers entities from `libs/users`
- **THEN** no entity-discovery error is thrown and all four tables are in the metadata

#### Scenario: Migration generated from entities
- **WHEN** `pnpm mikro-orm migration:create` is run after defining the entities
- **THEN** a migration file is generated containing `CREATE TABLE user`, `CREATE TABLE session`, `CREATE TABLE account`, and `CREATE TABLE verification` statements

### Requirement: Better Auth migration SQL is applied via MikroORM migration
The Better Auth schema SQL (generated by `pnpm better-auth generate`) SHALL be embedded in a MikroORM migration file so that MikroORM owns the migration lifecycle for the users-subgraph database.

#### Scenario: Migration runs successfully against PostgreSQL
- **WHEN** `pnpm mikro-orm migration:up` is executed with a reachable PostgreSQL instance
- **THEN** all Better Auth tables are created and the migration is recorded in the `mikro_orm_migrations` table

#### Scenario: Entities discoverable by glob
- **WHEN** the entity glob `libs/**/*.entity.ts` is scanned
- **THEN** the four entity files in `libs/users/src/lib/entities/` are discovered and loaded
